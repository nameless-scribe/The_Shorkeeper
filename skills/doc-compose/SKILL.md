【技能：文档撰写】

从零写一份新文档。固定流程是"问清 → 大纲确认 → 生成 → 汇报"，大纲没确认之前不生成文件。
改已有文件不是这里的事：Markdown 交给工作区文档维护，Word 原位修改另有工具。

一、问清（证据不足先问）
用户消息与附件里已经说清楚的不要再问；缺的用 `ask_user` 问，一次只问一件事，给选项，等回答后再问下一件。通常要清楚四件事：
1. 主题与用途：这份文档拿去干什么（对内汇报 / 给客户 / 存档备忘……）。
2. 读者：给谁看，决定口吻与详略。
3. 篇幅：一页要点 / 两三页 / 完整长文。
4. 必须包含的要点：用户点名要写进去的内容；素材在工作区文件里时用 `read_file` 读，路径含糊才 `list_dir`。
格式默认 Word（`.docx`）；用户提了 PDF 或 Markdown 就按用户说的，没提就不要问。

二、大纲确认
把大纲写在对话里：标题、各节标题、每节一两句话说明写什么，篇幅估计。然后用 `ask_user` 问一次："按这个大纲写？"（选项：就这样写 / 要改，改什么写在"其他"里）。
用户要改就改完再问一次；`ask_user` 返回失败（稍后再答、超时）就停下，说明大纲在对话里、文件没生成，不要替用户决定。
用户在最初的消息里已经给了完整大纲或结构时，可以跳过问清，直接确认这一步。

三、生成
- Word 用 `gen_docx`，PDF 用 `gen_pdf`，Markdown 用 `gen_markdown`。正文一律写 Markdown：`#`–`######` 标题、`-` / `1.` 列表（最多两级）、`| 表格 |`、`**粗体**`、`*斜体*`、`---` 分页；除此之外的语法会按原文当文字，不要用。
- 标题只在 `title` 里给一次，正文不要再重复一遍大标题。
- 路径放在工作区里，文件名用文档标题，如 `方案/客户培训方案.docx`；用户指定了路径就用用户的。
- 内容只写用户给的和问出来的；需要编数字、日期、人名时不要编，写成"待补：xxx"并在汇报里列出来。
- 一篇文档一次生成，不要拆成多个文件；超长时先与用户商量分册。

四、汇报
一句话给出路径，再列文档结构（各节标题）与需要用户补的"待补"项。不要把全文再复述一遍。
工具失败或用户拒绝写入权限时，如实说"文件没有生成"，把正文留在对话里供用户复制，不要声称已完成。
