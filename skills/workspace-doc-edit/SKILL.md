【技能：工作区文档维护】

## 适用场景
用户要求：更新/修改/写回/改状态/修订/保存 工作区内的 `.md`、`.txt` 等文本文件。

## 硬性流程（不得跳过）
1. `list_dir` 确认路径（禁止猜子目录或《》书名号文件名）。
2. `read_file` 读取**完整**当前内容。
3. 在内存中完成全部修改（见下方「多位置同步」）。
4. **`write_file` 整文件写回**（必须调用；不可只在回复里说「已更新」）。
5. **再次 `read_file`**，在回复中引用关键修改行的**原文**作为验收证明。

若第 4 步未执行或用户拒绝写入权限，必须如实告知「文件未修改」，不得声称已完成。

## 多位置同步（实施计划类文档）
更新某阶段 Pn 状态时，通常需**同时**修改这些位置（以 OA 实施计划为例）：
- **总体节奏表**：`| Pn | … | 状态列 |`
- **章节标题**：`## … Pn：…`
- **权限点交付清单**（若有）：`| Pn | … | 状态 |`

状态标记约定（与 P1/P2 已完成风格一致）：
| 状态 | 表内 | 章节标题 |
|------|------|----------|
| 待开始 | `⏳ 待开始` | `## Pn：…` |
| 进行中 | `🔄 **进行中**` | `## 🔄 Pn：…（进行中）` |
| 已完成 | `✅ **已完成**` | `## ✅ Pn：…（已完成）` |

改 P3 时**不要动** P1/P2 等其他阶段已有状态，除非用户明确要求。

## write_file 注意
- 必须写入**完整文件内容**（read 到的全文 + 你的修改），不要只传片段。
- `path` 与 read 时一致；覆盖前确认路径正确。
- 写入后用户聊天中会出现可点击打开的「相关文件」卡片。

## 禁止
- 未调用 `write_file` 就说「已写回 / 已更新完毕」。
- 只改回复里的表格不同步文件。
- 用 `gen_markdown` 覆盖已有大文件（除非用户要新建文件）；已有文件用 `read_file` + `write_file`。

## 与 Excel / 转 Markdown 技能并存
本技能只管文本类编辑；读 xlsx 用 Excel 技能，docx 转 md 用文档转 Markdown 技能。可同时启用，工具白名单取**并集**。
