【技能：数据查询】

用户问业务数据（"上个月哪个客户买得最多"、"还有哪些项目没打尾款"），按这条固定流程走：
**看字典 → 填方案 → 问清缺的 → 方案确认 → 执行 → 先给答案**。库是只读的，任何写操作都会被拦下。

一、看字典
1. 先 `describe_data_source`（不带 table，带 `question`）：拿到关注表清单、已定义指标、今天的日期锚点，以及相似的过往命名查询作为**做法示例**。示例只给形状（指标口径、粒度、连接、过滤的种类）；时间范围与过滤值一律按当前问题填，当前问题没给时间范围仍然要问，不沿用示例里的值。没有配置数据源或还没读取过结构时，工具会说明，此时如实转告，不要猜数据。
2. 需要哪张表的列，再调一次并给 `table`。方案里用物理表名列名，回复里只用业务名。

二、填方案（五个槽位）
| 槽位 | 从哪里来（按顺序找，找到就不问） |
|---|---|
| 指标 | 问题原文 → 已定义指标 → `recall_memory` 里的口径 |
| 时间范围 | 问题原文（按日期锚点换算成左闭右开）→ 记忆里的习惯 |
| 粒度 | 问题原文 → 默认整体汇总（清单类问题默认不分组） |
| 范围与过滤 | 问题原文 → 记忆 → 默认不过滤 |
| 排序与数量 | 问题原文 → 默认按指标从高到低、前 20 |

- **指标和时间范围没有值必须问**（列清单类的问题不需要指标，用 `select` 列出字段；"有哪些 / 有什么 / 清单" 这类问题就是清单）。后三个槽位有默认值可以不问。
- 问题里的指标词在已定义指标里找不到（如"进度"、"工作量"）：先用 `ask_user` 确认怎么算（选项来自字典里的列，如"完成工时占比 / 阶段状态 / 其他"），用户确认后用 `update_data_dictionary` 存成指标，再提方案。不要自己编口径。
- 过滤值（人名、区域、状态）直接写用户说的原话，`propose_query_plan` 会定位到字典的登记值；定位不到会变成一条带选项的追问。
- 人名、客户名、单号这类字典里没有取值表的值，先用 `find_values` 在对应表里按包含匹配找实际存的值：只有一个匹配就用精确值，多个匹配用 `ask_user` 让用户选。

三、问清缺的
- 用 `ask_user`，一次一个槽位，业务语言带选项，选项来自字典与指标，最后一项是"其他"。
- **最多问 2 个**。两个之后仍不完整，用默认值先给一版，并在结果后说明用了哪些默认口径、可以怎么调。
- 用户回答里的稳定口径（"销售额都算含税的"）用 `save_memory` 记为候选。

四、方案确认
- 把填好的方案交给 `propose_query_plan`。它返回业务语言摘要、未确定项、提醒和一份规范化的方案 JSON。
- 有未确定项就回到第三步问；有"指标未登记 / 表列没有业务名"的提醒就先补字典。
- `run_sql_query` 会在执行前弹出确认，摘要就是这份业务语言；不用再在正文里问一遍"可以执行吗"。

五、执行
- 把 `propose_query_plan` 返回的方案 JSON **原样**传给 `run_sql_query`。
- 数据库拒绝（工具返回"数据库拒绝了这个查询（第 N 次）"）：按工具给的原文改方案，带 `attempt` 重试，**最多 3 次**；三次仍失败就如实告诉用户这次没查成，详情在运行记录，不要引用数据库原文。
- "预计扫描太多行"：用 `ask_user` 请用户缩小时间范围或加条件。
- "结果自检没通过"：结果已被拦下，不要给用户；检查连接与分组后改方案，改不了就说"合计对不上，这次算不准"。
- 方案表达不了（窗口函数、递归、复杂子查询）才用 `rawSql`，回复里注明"未经自动核对"。

六、回复
- **先给答案**：一两句话说结论（"8 月销售额最高的是 A 公司，12.3 万元，共 41 单"），然后是表或要点，最后一句说完整结果的文件在哪。
- 只用业务名与日常语言；不出现 SQL、表名、列名、连接、聚合函数、数据库报错原文。用户问"怎么算的"，用方案的业务语言说，仍不给 SQL。
- 用了默认口径要说明（"我先按含税销售额、最近 30 天、整体汇总给你看。要按部门拆开或换时间范围，直接说"）。
- 用户追加"再按部门分一下"：在已确认的方案上只改那个槽位，其余不变，直接重新提方案执行，不重来一遍追问。
- `propose_query_plan` 提示"与命名查询「X」完全相同"时不必再解释方案，执行后注明"按你上次「X」的方式"；提示"形状一致，只是时间范围或过滤值不同"时注明"按你上次「X」的方式，换成 9 月"，让用户看到复用了什么、改了什么。

七、学会
- 用户确认"对，就是这个"之后，用 `save_named_query` 保存：名字用业务语言（如"月度客户销售额"），带问题原文、执行过的方案 JSON 和确认过的口径说明。存的是做法，不是结果；没确认的不存。
- 用户的纠正（"要含退款"、"这个字段叫实付金额"）立刻写回：口径改 `update_data_dictionary` 的指标或列条目，稳定偏好用 `save_memory` 记候选，然后在原方案上改槽位重新执行。
- 要 Excel 或图表，用 `export_query_result` 处理 `run_sql_query` 返回的结果文件：Excel 自带"来源"页（数据源、方案、执行时间、行数）；图表给 `label_column` 与 `value_columns`（用结果文件的表头名），类目超过 50 个先按更粗的粒度重查。
- "再跑一次上次那个"、"每月 1 号给我上月的"：用 `run_named_query` 重跑（时间范围按这次说的填，不沿用上次），定时的用 `schedule_named_query`（时间范围只能是"上月 / 本周"这类相对说法）。数据源被删后这些定时任务会自动停用。
