P2 取消后，P3 的三项调整

核心目标不变，数据来源和验收场景改为本地闭环。

移除

  • 邮箱、外部日历、联系人和云盘
  • OAuth、Token、第三方限流与外部写入
  • 外部消息触发与“会前准备”场景

保留

  • 主动收件箱、安静时段与频率限制
  • 承诺跟进、每日简报与晚间复盘
  • 通知原因、抑制原因和采纳反馈

补强

  • 持久事件、决策与投递账本
  • 跨重启去重和来源自动解决
  • 运行失败、知识变化和记忆冲突入口

统一的本地主动闭环

确定性规则先决定是否打扰，模型只能润色已经允许展示的内容。

本地真源待办、承诺、run、文档、记忆、调度
状态信号合并重复变化；启动 / 唤醒低频校对
事件账本稳定 dedupe key、版本、状态与解除条件
确定性策略紧急度、安静时段、频率预算、域静音
路由收件箱 / 延后 / 即时提醒 / 抑制
反馈打开、采纳、忽略、稍后与已解决

六阶段实施路线

先证明事件跨重启不重复，再做 UI 和弹窗路由。

00

事件契约与固定样本

2–3 天 · 不改变生产行为。

  • 事件类型、状态、紧急度和解除条件
  • 跨重启、改期、恢复、安静时段和风暴样本
  • 建立 test:p3 与跨阶段兼容入口
阶段出口

每类事件何时创建、解决、通知和抑制都有确定答案。

01

持久事件账本与本地采集器

4–6 天 · migration 0026。

  • events / decisions / deliveries / feedback
  • 状态信号合并、延迟校对、唤醒与兜底扫描
  • 内存 decision log 迁入 Repository
阶段出口

重复扫描、崩溃重启和休眠恢复只产生一条活动事件；来源解决后自动收口。

02

主动收件箱与来源回链

4–6 天 · 标题栏未读入口 + 侧栏。

  • 需要处理、稍后、已处理三类状态
  • 为什么出现、来源、紧急度和延后原因
  • 打开来源、忽略、稍后与已读操作
阶段出口

各 UI 状态、最小窗口和主题通过 Electron 检查；来源可以真实打开。

03

统一路由、跨重启去重与预算

4–6 天 · 原有提醒和每日管家接入统一 delivery。

  • inbox / notify / defer / suppress
  • 每小时与每日即时通知预算、域静音
  • 安静时段、snooze 和持久 delivery key
阶段出口

时钟变化、重复 signal 和多事件风暴不会重复轰炸；被抑制事件不会丢失。

04

四个本地纵向场景

4–6 天 · 不执行未经确认的修复动作。

  • 承诺守望与失败恢复
  • 知识守望与记忆守望
  • 早间简报和晚间复盘聚合高价值事件
阶段出口

事件从本地状态产生、统一路由、回链真源，并随真源解决自动关闭。

05

全局回归与两周真实使用

3–5 天 + 连续两周观察。

  • P0 / P1 / S2–S5、全量、Electron 与打包回归
  • 模拟 UI 证据与真实体验指标分开
  • 记录重复、漏报、打开、采纳、忽略和 snooze
阶段出口

连续两周无重复轰炸，关键承诺没有漏跟进。

四种路由

“不弹窗”不等于“丢弃”，普通事项仍留在收件箱等待用户处理。

默认

主动收件箱

普通逾期、文档变化、单次运行失败和待确认记忆。

少量

即时提醒

显式到点提醒、即将错过的高优先级承诺和需立即处理的本地故障。

安静时段

延后

事件先记账，弹窗推迟到安静时段结束；不会反复重新排期。

不打扰

抑制

重复、已解决、已忽略、预算耗尽或主动性全局关闭。

影响面

没有 OAuth 和外部网络风险，主要风险转为重复打扰与本地事件一致性。

模块变化风险控制方式
数据库事件、决策、投递和反馈账本中高单一增量 migration、双 adapter、限长脱敏、保留策略
调度器提醒与每日管家统一 delivery高先 shadow decision 再切路由；跨重启幂等键
P0 / P1领域状态成为事件来源中高collector 只读投影；不复制正文，不改变真源
TaskRun失败和中断进入收件箱中只展示真实步骤；禁止自动重放副作用
UI标题栏入口、未读数和收件箱侧栏中复用现有侧栏与 keeper token；主题和最小窗口验收
启动 / 退出增加有界校对与事件推送中启动后延迟、合并、取消、宽限期和故障隔离

最终完成证据

连续两周无重复轰炸，关键承诺没有漏跟进；打开率、采纳率、忽略率和 snooze 后重复率来自真实使用记录。

停线条件

跨重启重复通知、事件写回污染领域真源、启动被扫描阻塞、保存敏感正文、解决后无法自动关闭、关闭主动性后仍弹窗，或失败 run 被自动重放。
