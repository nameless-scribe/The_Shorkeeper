# P7 · 数据源查询实施计划

> 计划验收入口：逐阶段补齐 `pnpm test:p7`
>
> 阶段编号沿用 P 系列。P7 是已取消的 P2（外部连接器）的收窄版：只连数据库、只读、
> 把"我说想法 → 它组 SQL → 出 Excel 或图表"跑通。依赖 P5 的产出工具与 P6 的追问机制。

当前状态（2026-09-14）：**未开工**。本文是开工前的契约，不是验收记录。

**用户已明确的范围（2026-09-14）**：第一版连 **MySQL 与 SQL Server**，其它数据库后续再加。

---

## 1. 目标与边界

**要解决的**：用户用自己的业务语言提问，助理读懂库结构、在口径不明时先问、生成只读 SQL、
校验后执行、把结果变成 Excel 或图表，并把确认过的问题沉淀为可复用的命名查询。

**不解决的**：任何写库操作、跨库联查、通用 SQL 编辑器、除 MySQL / SQL Server 之外的数据库。见第 7 节。

**蓝图约束**："不开放高危系统权限"。外部数据库对本项目是高危面，因此第一版**连接层就只读**，
不是靠提示词约束模型不写。

---

## 2. 为什么不是"支持各种数据库"

"各种数据库"会把工作量花在驱动兼容上，而用户真正要的是"它懂我的业务、能出我要的结果"。
后者的核心零件——结构卡片、口径追问、SQL 校验、命名查询、带来源的产物——与数据库种类无关。
先在两种库上把这些零件做扎实，再加驱动是加法；反过来先铺驱动，零件永远做不深。

MySQL 与 SQL Server 各自的特点决定了几处分叉，第 3 节逐条写明。

## 3. 设计决定

### 3.1 连接与只读

| | MySQL | SQL Server |
|---|---|---|
| 驱动 | `mysql2`（纯 JS） | `mssql`（基于 tedious，纯 JS） |
| 会话级只读 | `SET SESSION TRANSACTION READ ONLY` | 无会话只读开关；依赖 3.2 的校验器与只读登录 |
| 建议账号 | 只授 `SELECT` | 只在 `db_datareader` 角色 |
| 行数限制 | 追加 `LIMIT n` | 注入 `TOP n`（无 `TOP` 时） |
| 结构读取 | `information_schema` | `INFORMATION_SCHEMA` + `sys.foreign_keys` |

设置页在"测试连接"时**主动探测账号权限**：能执行 `INSERT` 试探（在事务里回滚）的账号标为
"⚠ 该账号有写权限，建议换只读账号"，但不拒绝使用。

凭证：与 P4 转写凭证同一做法，密码经系统凭据存储加密落库，设置页只回传掩码。

### 3.2 SQL 校验器（纯函数，本阶段的核心零件）

执行前必须通过，任何一条不过就拒绝并把原因告诉模型：

- 只允许一条语句；去掉尾部分号后不得再出现分号。
- 首个关键字只能是 `SELECT` / `WITH`；`WITH` 的主体也必须是 `SELECT`。
- 黑名单关键字（不区分大小写、按词边界匹配）：`INSERT UPDATE DELETE MERGE DROP ALTER CREATE TRUNCATE GRANT REVOKE EXEC EXECUTE CALL INTO OUTFILE LOAD_FILE xp_ sp_ OPENROWSET OPENQUERY BULK`。
- 不含注释（`--`、`/* */`），避免用注释绕过匹配。
- 没有行数限制的自动加上（默认 500，上限 5000）。
- 校验器不是 SQL 解析器，它是**保守的拒绝器**：宁可拒绝一条合法的复杂查询让模型改写，也不放过一条可疑的。

### 3.3 结构卡片

连接成功后读取表、列、类型、主键、外键、每张表的行数估计、每列前 3 个非空样例值（文本列截断 40 字），
生成一份 Markdown 结构卡片缓存在 `userData`，带哈希与抓取时间，设置页可手动刷新。

注入策略：不整份进上下文。模型先 `describe_data_source` 拿到表清单与一句话描述，再按需要取具体表的列。
超过 200 张表的库先让用户在设置页勾选"关注的表"。

样例值有隐私风险：**样例值只进缓存不进日志与运行记录**，且设置页可关闭样例值抓取。

### 3.4 工具

| 工具 | 契约 | 说明 |
|---|---|---|
| `list_data_sources` | 只读 | 名称、类型、库名、上次连通状态 |
| `describe_data_source` | 只读 | 结构卡片（整库摘要或指定表） |
| `run_sql_query` | `risk: 'medium'`、幂等、`evidence: 'output'` | 参数：`source`、`sql`、`max_rows?`。先过校验器，再执行；返回列名、行数、前 20 行预览，**完整结果写成工作区 `.csv` 产物**并返回路径 |
| `save_named_query` | `LOCAL_UPSERT_CONTRACT` | 把确认过的"问题 → SQL"存成命名查询 |
| `run_named_query` | 同 `run_sql_query` | 按名字重跑，供定时任务用 |

`run_sql_query` 的确认弹窗里显示**将要执行的 SQL 与目标数据源**，用户看得到发出去的是什么。
`risk: 'medium'` 意味着走用户的权限策略（默认确认），不强制每次确认——那会把"再按月分一下"这种迭代变成折磨。

结果不进上下文的规则与 P4 逐字稿一致：模型看到的是列名、行数与前 20 行；要全量就读 `.csv` 产物。

### 3.5 产出与来源

- Excel：`gen_xlsx`（P5 之前即可用）。
- 图表：`gen_chart`（P5.3）。
- 每份产物**第一行或元数据里带来源**：数据源名、SQL、执行时间、行数。Excel 加一张 `来源` 工作表；图表 SVG 里加 `<desc>`。
- 命名查询的产物文件名带查询名与日期，定时重跑不覆盖历史。

### 3.6 追问口径（依赖 P6）

技能规则：遇到以下情况**先 `ask_user` 再写 SQL**：指标口径（含税 / 不含税、是否含退款）、
时间基准（下单 / 付款 / 发货日期）、范围（全部门 / 某部门）、去重口径。
问过的口径作为记忆候选保存，命名查询里也记录口径说明，下次同类问题直接复用。

### 3.7 持久化

新增 migration，三张表：

| 表 | 关键列 |
|---|---|
| `data_sources` | `id`、`name`、`kind (mysql / mssql)`、`host`、`port`、`database`、`user`、`password`（加密）、`options_json`（ssl、超时、关注的表、是否抓样例值）、`last_ok_at`、`last_error`、`writable_account`（探测结果） |
| `named_queries` | `id`、`data_source_id`、`name`、`question`、`sql`、`notes`（口径说明）、`created_at`、`last_run_at`、`last_row_count` |
| `query_runs` | `id`、`run_id`、`data_source_id`、`named_query_id?`、`sql`、`status`、`row_count`、`duration_ms`、`artifact_path`、`error`、`started_at`、`finished_at` |

`query_runs` 不存结果数据，只存路径与统计，与转写账本同一原则。

### 3.8 设置页

设置 → 数据源：新增 / 编辑 / 删除；测试连接（连通、权限探测、表数量）；刷新结构卡片；
关注的表；样例值开关。凭证输入框留空不改，与转写凭证一致。

## 4. 实施阶段

### P7.0 — 契约与校验器（2 天）

- SQL 校验器（3.2）纯函数与固定样本：合法 `SELECT`、`WITH`、含子查询；被拒的 `UPDATE`、
  多语句、注释绕过、`INTO OUTFILE`、`EXEC`、`OPENROWSET`；行数限制注入（MySQL `LIMIT` / SQL Server `TOP`）。
- 结构卡片格式化纯函数与样本（含 200 张表的截断、样例值截断）。
- 数据源、命名查询、查询运行的类型与仓储。
- 建立 `pnpm test:p7`。不发任何真实数据库请求。

**阶段出口**：校验器对固定样本有确定判定；不改变任何生产行为。

### P7.1 — 连接器与设置页（3–4 天）

- `mysql2` 与 `mssql` 接入，加 vite externals 与打包白名单。
- 连接层统一接口：`connect / ping / probeWritable / fetchSchema / query(sql, maxRows, timeout, signal)`；
  MySQL 会话只读；查询超时 30 秒且可取消。
- 设置页（3.8）与凭证加密。
- 真实验证：各连一个真实库，`ping`、权限探测、结构抓取、一条查询。

**阶段出口**：两种库都能在设置页连通并拿到结构卡片；写权限账号被标出。

### P7.2 — 工具与技能（3 天）

- 五个工具（3.4）。
- `data-query` 技能：理解问题 → `describe_data_source` → 口径追问（3.6）→ 写 SQL → `run_sql_query` →
  预览 → 用户确认结果正确 → `save_named_query` → 导出。
- 固定样本：校验器拒绝时模型改写；预览行数与产物行数一致；同一问题第二次直接命中命名查询。

**阶段出口**：一个真实业务问题走完"提问 → 追问 → SQL → 结果 → 保存"。

### P7.3 — 导出与图表（1–2 天）

- 结果 → `gen_xlsx`（带来源工作表）→ `gen_chart`（3.5）。
- 固定样本：多列结果转 Excel 类型正确（数字不变文本）；日期列格式；图表类目超限时提示聚合。

**阶段出口**：同一份结果能一句话变成 Excel 或图表，且都能追溯到 SQL。

### P7.4 — 命名查询定时重跑（1–2 天）

- `run_named_query` 接 P3 的定时任务，产物按日期命名，完成后走现有通知。
- 固定样本：定时任务失败不静默；数据源被删除时定时任务自动停用并提示。

### P7.5 — 回归与真实使用（2 天 + 观察）

- `pnpm test:p7`、全量、`typecheck`、`build`、`test:ui:strict`、`test:electron`。
- 真实使用记录：至少 10 个真实业务问题，记录追问次数、SQL 一次正确率、用户改写次数、耗时。

## 7. 明确不做

- **不做任何写库**：没有 `run_sql_write`，校验器也不给"用户确认后可以写"留口子。将来若要做，是另一个阶段的契约。
- **不做跨库联查**：一次查询只对一个数据源。
- **不做通用 SQL 编辑器 / 数据库管理界面**：这是助理，不是客户端。
- **不连 PostgreSQL、Oracle、SQLite 外部文件等**：等真实需求，按 3.1 的接口加驱动即可。
- **不把结果全量注入上下文**：预览 20 行，其余走产物。
- **不在日志、运行记录、通知里出现样例值与结果数据**。
- **不做交互式图表与仪表盘**。
- **不做自然语言到 SQL 的本地模型**：用当前对话模型加结构卡片加校验器。

## 8. 推荐开工顺序与停线条件

建议顺序：**P7.0 → P7.1 → （等 P6.1）→ P7.2 → P7.3 → P7.4 → P7.5**。
P7.0 与 P7.1 可以在 P5 / P6 进行中并行开工，因为它们不依赖任何未完成阶段。

出现以下任一情况立即停止扩大范围：

- 任何路径能把非 `SELECT` 语句发到数据库；
- 校验器为了放行某条查询而加白名单例外；
- 密码以明文出现在数据库、日志或渲染层；
- 结果数据或样例值进入日志、运行记录或通知；
- 未经确认的 SQL 被执行（权限策略为"确认"时）；
- 单次查询无上限、无超时或不可取消；
- 为了兼容第三种数据库而推迟校验器与命名查询；
- 模型在口径不明时不问而直接猜。

## 9. 待确认

- **SQL Server 的连接方式**：Windows 集成认证还是 SQL 登录。`mssql` 两种都支持，但集成认证在打包后的 Electron 里需要验证。开工前问用户实际环境。
- **网络位置**：数据库在内网还是公网，是否需要 SSL。影响 `options_json` 的默认值。
- **表数量级**：决定 3.3 的"关注的表"是否第一版就要做。
- **是否需要参数化查询**（如"按输入的部门查"）：影响命名查询是否带参数。第一版倾向不带，用 P6 追问代替。
