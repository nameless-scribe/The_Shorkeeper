# S5 守岸人私人助理化推进方案

## 目标

S5 不重写 Agent、工具或权限系统，而是在 S0-S4 的稳定底座之上增加一层可测试的私人助理契约：

- 人设决定表达方式，但不覆盖事实、权限和失败状态。
- 助理模式决定本轮的工作倾向，但不改变工具权限。
- 记忆策略决定什么可以长期保存，避免把每句对话都变成记忆。
- 主动性策略决定何时静默执行、提醒或请求确认，避免“热心”变成打扰。

## 当前基础与缺口

已有能力：

- `src/config/persona.ts` 和 `PersonaPage`：可编辑、可恢复的人设 System Prompt。
- `src/agent/stable-context.ts`：每轮稳定人设、工具规则和上下文优先级。
- `src/memory/summarizer.ts`：按轮次异步提取结构化长期记忆。
- `src/memory/long-term.ts`：长期记忆 upsert、去重、检索和异步向量补全。
- RAG、工作区、待办、定时提醒和工具权限已经具备稳定入口。

主要缺口：

- `focus` / `organize` / `review` / `companion` 尚未有统一的会话级状态和提示契约。
- 自动记忆提取成功后会直接 upsert，缺少候选、置信度和确认边界。
- 主动提醒已有定时任务确认链路，但还没有统一的“静默 / 提醒 / 必须确认 / 禁止打扰”策略。
- 人设当前是自由文本，缺少对办事风格、拒绝方式和事实优先级的结构化验收。

## 分阶段推进

### S5.0：契约冻结与场景基线

先只定义规则和验收，不改变默认运行行为。

交付物：

- `AssistantMode`：`focus`、`organize`、`review`、`companion`。
- 模式作用域定义为“会话级”，默认 `focus`；模式切换必须来自用户或明确的 UI 操作，不能由模型自行永久切换。
- `AssistantActionPolicy`：`silent`、`notify`、`confirm`、`deny` 四种动作级别。
- 人设、事实准确性、权限和工具错误的优先级契约。
- 至少 6 个固定场景：普通闲聊、推进多步任务、整理工作区、知识库问答、审核计划、创建提醒。
- 每个场景记录：预期模式、可用工具、是否允许副作用、是否必须确认、失败后的用户提示。

验收：

- 模式不会绕过 S3 权限和确认规则。
- `companion` 不会因为聊天内容自动创建提醒、写文件或保存长期记忆。
- `review` 默认先读后评，不直接修改文件或计划。
- `focus` 可以推进任务，但仍必须遵守工具失败和写入确认链路。

### S5.1：人设契约与模式提示层

在现有 `stable-context` 之上增加结构化模式片段，保留当前自定义 System Prompt 的兼容性。

- 人设正文继续由用户编辑；模式只追加短小、可审计的行为约束。
- 模式提示不得重复注入工具说明、RAG 事实或权限说明。
- 模式切换只影响当前会话后续轮次，不回写历史消息。
- 为四种模式分别增加 prompt contract 测试和冲突优先级测试。

建议实现边界：

- `src/assistant/mode.ts`：模式类型、默认值、模式描述和规范化。
- `src/assistant/mode-prompt.ts`：模式提示片段，不直接执行工具。
- `src/agent/context-builder.ts`：只负责注入当前模式片段。

### S5.2：记忆候选与确认策略

把“提取事实”和“写入长期记忆”分开，降低误记忆风险。

- 明确区分稳定偏好/称呼/习惯、任务上下文、临时信息和敏感信息。
- 自动提取先生成候选：`key`、`content`、`confidence`、`reason`、`requiresConfirmation`。
- 明确确认的 `save_memory` 继续直接写入；自动提取只允许低风险、高置信度类别静默保存。
- 用户拒绝或删除后，不能在下一轮自动恢复同一候选。
- 增加记忆查看、编辑、删除的可验证入口；不把删除仅实现成 prompt 指令。

兼容策略：

- 保留现有 `always` / `every_n` / `manual` 设置。
- S5.2 初期默认沿用当前配置，新增策略只在测试覆盖后逐步启用。
- 任何向量补全失败都不能阻止文本记忆的确认、编辑或删除。

### S5.3：高频助理场景闭环

**阶段结果（2026-09-11）**：六种固定场景已写入 `src/assistant/scenarios.ts`。`organize` 与 `companion` 补齐成功、工具失败、取消、权限不足、需要确认五条路径，并继续复用 S3 权限而不是另开白名单。

按用户价值而不是按模块推进，每个场景都要有“理解 → 执行 → 反馈 → 记忆/待办”的闭环。

优先顺序：

1. `focus`：多步任务和项目计划维护。
2. `organize`：工作区文档整理、知识库归档和资料检索。
3. `review`：计划、文档、代码和待办审核，默认只读分析。
4. `companion`：陪聊、情绪支持和低打扰上下文，不新增自动副作用。

每个场景至少覆盖成功、工具失败、用户取消、缺少权限、需要确认五条路径。

### S5.4：主动性与降噪

**阶段结果（2026-09-11）**：提醒展示走 `evaluateReminderDelivery`；关闭、重复和周期任务安静时段抑制弹窗。一次性提醒在安静时段推迟到结束时间。决策写入有上限的内存记录，抑制不会改变会话成败。

最后再开放主动能力，避免把定时任务和后台能力直接扩大。

- 静默：整理已明确授权的上下文、生成草稿、更新本轮执行状态。
- 提醒：任务即将到期、失败需要用户处理、用户明确订阅的周期提醒。
- 确认：写文件、创建/删除提醒、保存高敏感或关系类记忆、影响外部系统的操作。
- 禁止打扰：用户明确关闭、安静时段、连续重复提醒、无明确收益的主动消息。

现有定时任务的显式确认链路继续作为硬边界；S5 不允许通过新模式绕过它。

### S5.5：总体验收

**阶段结果（2026-09-11）**：`pnpm test:s5` 与 [S5 验收集](S5-ACCEPTANCE.md) 已固定自动化基线。三条 Electron 实机路径是建议的使用走查，不作为框架稳定化的阻断项。

- 固定场景集在四种模式下行为稳定。
- 普通聊天和办事请求的工具使用差异可解释。
- 自动记忆不会把临时内容、敏感内容或模型猜测直接长期保存。
- 主动提醒可关闭、可追踪、可去重，且不会改变会话成功/失败状态。
- 人设、模式、记忆和主动性规则均有单测；桌面端三条场景可作为使用走查，不阻断 S5 收口。

## 当前进度

S5.0-S5.4 的代码契约已落地，S5.5 自动化验收已建立：

- S5.0：六种固定场景写入 `src/assistant/scenarios.ts`，模式仍为会话级，默认 `focus`。
- S5.1：结构化模式提示已接入 `context-builder`，聊天页可切换并显示模式说明。
- S5.2：记忆候选表、确认/拒绝 IPC、自动提取分流，以及设置页对已保存记忆的查看/编辑/删除可用。删除带 key 的记忆会拒绝同一事实，避免自动提取静默恢复；明确的 `save_memory` 仍可写入。
- S5.3：`focus` / `organize` / `review` / `companion` 均复用现有失败、取消和权限确认链路；后两者补齐五条路径回归。
- S5.4：提醒可见性决策可追踪；一次性提醒在安静时段推迟而不是被消费。
- S5.5：`pnpm test:s5` 与 [S5 验收集](S5-ACCEPTANCE.md) 已固定。三条 Electron 实机路径是使用走查，不阻断框架稳定化收口。

高置信度、非敏感的稳定事实才会静默保存，其余合法候选进入待确认队列，非法键直接拒绝；`companion` 不会自动提取记忆。默认模式仍为 `focus`，没有扩大主动提醒行为。

## 下一轮推进范围

S5 代码与自动化验收已收口，框架稳定化阶段结束。剩下只是可选的桌面实机走查，不再开新的稳定化子阶段。

## 明确不做

- S5 不接入私人云端模型。原 S6 只是后续想法，不在本轮范围。
- S5 不让模型自行修改权限、静默创建提醒或扩大工具白名单。
- S5 不用一次性重写现有人设；先通过兼容层和固定场景逐步收敛。
- S5 不把陪伴模式与“自动保存所有对话”绑定。
