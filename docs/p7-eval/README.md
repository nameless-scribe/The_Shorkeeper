# P7 评测集

`questions.json` 是 P7 的硬指标来源（计划 §3.7、§11.6）：20 个你真正会对数据库问的问题，越口语越好。
没有它，"效果好不好"没有答案。P7.0 只要问题与期望要点，不需要能跑；`pnpm test:p7:eval`（P7.2）会对真实库跑并输出通过率。

## 怎么填

每一项：

```json
{
  "id": "q01",
  "question": "看看上个月哪个客户买得最多",
  "expect": {
    "slots": { "指标": "销售额", "时间范围": "上个月", "粒度": "客户" },
    "rowCountBetween": [1, 20],
    "mustNotContain": ["SELECT", "orders"]
  },
  "notes": "随便写点备注，比如这个问题上次实现答错在哪"
}
```

`expect` 里每个字段都可选：

| 字段 | 含义 |
|---|---|
| `slots` | 期望方案里的槽位要点，用业务语言写（指标 / 时间范围 / 粒度 / 范围过滤 / 排序数量） |
| `rowCountBetween` | 结果行数区间 `[下限, 上限]` |
| `aggregate` | `{ "column": "订单数", "equalsQueryName": "月订单数" }`：某列的合计要与一条命名查询的结果一致 |
| `mustAsk` | `true` 表示这是笼统问题，期望助理先追问（至少要有 5 个） |
| `mustNotContain` | 回复里不得出现的字符串：SQL 关键字、表名、列名（非开发者视图下一律不许出现） |

只写 `id` 与 `question` 也可以，期望要点可以在 P7.2 跑出第一版结果后再补。

`pnpm test:p7` 会校验这个文件的格式；数量不足只告警不失败。
