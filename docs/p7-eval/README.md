# P7 评测集

`questions.json` 是 P7 的首轮评测集（计划 §3.7、§11.6）：用户确认先用现有 10 个真实问题，其中 4 个需要追问；后续可从真实使用中自然增补，不为凑数量编问题。
没有真实问题，"效果好不好"没有答案。`pnpm test:p7:eval` 会对真实库跑并输出一部分自动化指标，但不能单独证明业务答案正确。

## 怎么填

每一项：

```json
{
  "id": "q01",
  "question": "看看上个月哪个客户买得最多",
  "expect": {
    "slots": { "指标": "销售额", "时间范围": "上个月", "粒度": "客户" },
    "rowCountBetween": [1, 20],
    "mustNotContain": ["SELECT", "orders"]
  },
  "notes": "随便写点备注，比如这个问题上次实现答错在哪"
}
```

`expect` 里每个字段都可选：

| 字段 | 含义 |
|---|---|
| `slots` | 期望方案里的槽位要点，用业务语言写（指标 / 时间范围 / 粒度 / 范围过滤 / 排序数量） |
| `rowCountBetween` | 结果行数区间 `[下限, 上限]` |
| `aggregate` | `{ "column": "订单数", "equalsQueryName": "月订单数" }`：某列的合计要与一条命名查询的结果一致 |
| `mustAsk` | `true` 表示这是笼统问题，期望助理先追问（首轮 10 题中至少 4 个） |
| `mustNotContain` | 回复里不得出现的字符串：SQL 关键字、表名、列名（非开发者视图下一律不许出现） |

只写 `id` 与 `question` 也可以，期望要点可以在 P7.2 跑出第一版结果后再补。

`pnpm test:p7` 会校验这个文件的格式；不足 10 题或 4 道需追问题只告警不失败。当前无头评测器会检查追问次数、是否执行、行数范围和回复中的技术词；`slots` 与 `aggregate` 目前只记录期望，不做自动核对，业务口径和结果数值必须人工对照。

无头评测会调用真实模型并产生费用，自动批准工具权限，还会在应用数据库里创建和删除评测会话、可能生成工作区文件；应用正在使用真实配置时，不要把它当成只读健康检查直接运行。先在应用内逐题看方案、确认查询并人工核对结果。
