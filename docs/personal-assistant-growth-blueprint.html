产品北极星

NORTH STAR

不是“什么都会回答”，而是“了解你的目标和习惯，能安全地替你推进事务，失败可恢复，完成有证据，并在合适的时候主动跟进”。

统一的助理闭环

“验证”和“学习”决定她是否可信，以及是否真的越来越懂你。

01

理解

识别目标、约束与成功标准。

02

取上下文

获取人设、记忆、知识、日程与任务。

03

规划

生成可中断步骤，标注风险与确认点。

04

执行

选择能力，先预览再执行副作用操作。

05

验证

读回文件或核对外部系统最终状态。

06

交付

说明完成项、未完成项和产物位置。

07

学习

提取承诺与记忆候选，按策略保存。

建设顺序

点击每个阶段即可展开。先让助理可靠地办完一件事，再连接更多系统。

P0 · 闭环骨架（2–3 周）

把一次聊天升级为可追踪、可恢复、可验证的办事过程。

  • 新增 Goal、Commitment、TaskRun、Approval、Artifact。
  • 任务支持等待确认、失败恢复、重启续跑与完成验证。
  • 工具声明风险、幂等、预览、可撤销和完成证据。
  • 支持直接创建待办。
  • 打通每日简报到晚间复盘。
完成证据中途退出后仍能继续；任何“已完成”都有工具结果或产物。
P1 · 真正懂你（3–5 周）

把零散记忆升级为有来源、时效和冲突关系的个人模型。

  • 区分身份、偏好、关系、事件、目标、习惯和程序性偏好。
  • 记录来源、置信度、有效期、敏感等级和替代关系。
  • 新事实不直接覆盖旧事实，冲突内容进入确认。
  • 知识库增加持续同步、引用回链和过期提示。
完成证据她能解释使用了哪条记忆，偏好变化后不会继续引用冲突旧事实。
P2 · 连接现实世界（4–8 周）

通过统一连接器层处理日历、邮件、联系人、任务和云盘。

  • 统一内置工具、Skill、MCP 与第三方连接器。
  • OAuth 与 API Key 只进入安全存储。
  • 写操作提供预览、差异、确认、幂等和撤销。
  • 提供健康检查、限流、降级和重新授权入口。
完成证据完成“读邮件承诺 → 查日历 → 拟回复 → 确认后发送”的链路。
P3 · 克制的主动性（持续迭代）

会主动跟进承诺，但不制造打扰。

  • 截止时间、文档变化、任务失败和外部消息统一为事件。
  • 普通建议进入主动收件箱，紧急事项才即时通知。
  • 建立每日简报、会前准备、承诺追踪和晚间复盘。
  • 记录通知原因、抑制原因、反馈和采纳率。
完成证据连续两周无重复轰炸，关键承诺没有漏跟进。

首个 Sprint：每日管家闭环

01

这是检验整体架构最划算的第一个真实场景。

  1. 新增五类领域对象和数据库迁移。
  2. 让任务可暂停、等待确认、失败恢复和重启续跑。
  3. 增加直接创建待办的能力。
  4. 早间汇总天气、待办、日程和承诺。
  5. 用户调整后真正写入待办与提醒。
  6. 晚间更新状态，只提取少量高价值记忆候选。
  7. 验收：每个“已完成”都有工具结果或产物证据。

暂时不要做

不要急着训练私人模型

先用真实场景评测确认瓶颈来自模型、提示词、上下文还是工具链。

不要过早引入重型知识架构

先完善来源、引用、版本和同步，再考虑 Graph RAG 或独立向量数据库。

不要赋予无审计的系统权限

发送、购买、删除和覆盖必须可预览、需确认、有审计，最好支持撤销。

不要把全部聊天写成长记忆

保存稳定且有价值的信息；敏感、关系和低置信内容进入待确认队列。

架构原则：人设负责“怎么说”，个人模型负责“知道什么”，任务系统负责“正在做什么”，工具系统负责“能改变什么”，权限系统负责“什么情况下可以改变”。
