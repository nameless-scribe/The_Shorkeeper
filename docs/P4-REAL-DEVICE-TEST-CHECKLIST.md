## 1. 转写链路（不需要麦克风）

**先绕开应用验凭证：**

```
pnpm asr:probe D:\SQLlite\workspace\测试会议.wav 16k_zh_en
```

通过的标志：打印 `code: 0`、时长约 58 秒、若干句子、说话人数 ≥ 1。
不通过时按第 12.2 节的症状表处理，问题一定在凭证、服务开通或网络，与应用无关。

**再在应用里跑：**

```
pnpm dev
```

对助理说：`把 测试会议.wav 转写成逐字稿`

逐项打勾：

- [x] 弹出权限确认（`transcribe_audio` 是高风险工具，任何权限策略下都必须弹）
- [x] 确认后等待，短音频应在 10 秒内返回（实测 1.7 秒）
- [x] 回复只给路径、时长、句数、说话人数和前 200 字预览，**没有倒出全文**
- [x] `D:\SQLlite\workspace\测试会议.transcript.md` 出现，带时间戳和说话人标签（2 位说话人全部分对）
- [x] 设置 → 运行记录 末尾出现「录音转写」段，状态"已完成"
- [x] 再说一次同样的话：账本按文件哈希去重，**不应再次计费**，回复应说明已有结果
- [x] 权限确认时点拒绝：不产生文件、不留"已完成"记录
- [ ] 转写中点取消（用长录音才来得及）：记录状态为"已取消"，用的是灰色而非红色 —— **推迟到有长录音**，不阻塞 P4.4
- [ ] 转写中直接关闭应用再重启：残留记录被收口为"失败"，原因是"应用退出" —— **推迟到有长录音**，不阻塞 P4.4

## 2. 聊天框语音输入（P4.1，需要麦克风）

前置：设置 → 语音，确认「语音输入」开启；这条路走的是百炼 Paraformer，不用腾讯云凭证。

**2026-09-14 第一次点麦克风就失败**：报 `Unable to load a worklet's module`，语音通话同样不可用。
根因是 9 月 12 日加的 CSP 拦下了 blob 方式加载的 AudioWorklet，与麦克风设备、蓝牙耳机无关。
已改为同源静态文件加载（见计划 10.8）。**复测前先在应用里按 Ctrl+R 重载页面**，让新代码生效。

**同日第二个问题**：麦克风修好后语音通话仍一直"正在聆听"、无反应、无报错。根因是 `useCallVad` 的
"已销毁"标志在 StrictMode 双挂载后没有复位，VAD 从未启动，只在 `pnpm dev` 下出现（见计划 10.9）。
已修复；复测时**挂断后重新打开通话窗口**即可加载新代码。

一个已知风险：实时识别的 WebSocket 默认连 `dashscope.aliyuncs.com`，而 `.env` 里的对话接入点是业务空间地址。业务空间的 Key 若不能直接用于公共 DashScope 端点，会在这里第一次暴露。出现鉴权失败时，在 `.env` 设 `VOICE_STT_ENDPOINT` 指向业务空间对应的 WebSocket 地址再试。
