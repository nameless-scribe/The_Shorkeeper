## 1. 为什么还需要这份计划

S0-S5 已经完成了第一轮框架稳定化，Skill、Agent、模型适配、调度器和语音也完成了专项补强。但“已有测试全部通过”只说明已定义的行为没有回归，不能证明模块设计和文档契约没有遗漏。

本轮不再按功能名称检查，而是对每个现有模块固定执行六轴复审：

1. 正常路径与真实产物。
2. 运行中状态突变和配置切换。
3. 畸形、缺失、超大或恶意输入。
4. 长时间、系统计时上限和容量边界。
5. 重复请求、并发、重入和幂等。
6. 成功、失败、取消、窗口关闭及应用退出后的资源释放。

复审发现问题时，必须先补失败样例或故障注入，再修实现；不能只修改说明文档，也不能只针对当前现象打补丁。

## 3. 推进纪律

每个缺陷固定经过以下闭环：

1. **记录风险**：说明触发条件、影响范围和现有证据。
2. **建立复现**：优先自动化测试；硬件或系统行为无法自动化时建立可重复脚本和人工步骤。
3. **最小修复**：修责任边界，不把异常吞掉，不扩大功能范围。
4. **模块回归**：执行该阶段专用测试、类型检查和差异检查。
5. **全量回归**：阶段收口时执行完整测试、构建和对应运行时验收。
6. **更新契约**：同步设计文档、验收集和本计划进度。

任何一项出现以下情况都不能标记完成：

- 失败被误报成成功。
- 取消后仍继续写数据库、文件或界面状态。
- 并发操作可能覆盖新状态或重复产生副作用。
- 成功、失败或退出后仍遗留计时器、监听器、句柄、临时文件或活动任务。
- 只能依赖理想 mock 通过，真实产物没有验证。
- 文档描述与当前实现不一致。

## H1：知识库、RAG 与工作区六轴复审

**目标**：确保长期导入、更新、删除和检索不会产生旧数据回流、部分提交、孤儿文件或无上限资源占用。

### H1.1 状态与配置突变

- 导入或重建过程中切换 Embedding 配置，确认一次任务使用原子快照，不能混用模型、地址、密钥或向量维度。
- 文档计算向量期间被删除、替换或 supersede，旧任务不得把文档恢复成可检索状态。
- 重建列表运行期间新增、删除或更新文档，最终统计和状态必须可解释。
- 应用退出或数据库关闭时，中止尚未完成的导入、重建和查询。

### H1.2 畸形与容量输入

- 空内容、损坏 PDF/DOC/DOCX、扩展名与内容不符、非法 UTF-8 和异常超长单行。
- 路径不存在、目录冒充文件、符号链接变化和读取过程中文件被替换。
- IPC 直接传入空 ID、超长 ID、非字符串路径和超量路径列表。
- `importTextAsKnowledge` 等绕过文件入口的文本同样需要容量上限。
- Embedding 返回空数组、批次数量不符、维度中途变化、NaN/Infinity 或超大响应。

### H1.3 并发、重入和幂等

- 同一文档的导入、重建、删除必须有明确互斥或代际所有权。
- 多次点击全量重建不能并行改写同一批数据。
- 排队中的导入被取消时，不得在轮到它后继续创建文件和数据库记录。
- 工作区同时导入同名文件时，目标名分配必须原子，不能相互覆盖。
- 相同内容、相同来源新版本和无来源同标题的去重/版本号在并发下保持唯一。

### H1.4 文件与数据库一致性

- 数据库成功、文件失败；文件成功、数据库失败；清理失败；隔离恢复失败分别故障注入。
- 工作区复制采用临时文件、原子落位和读回校验，失败不留下半文件。
- 删除后检查文档、chunks、FTS、向量、缓存和受管文件均不再参与检索。
- 启动时识别并处理 `.trash`、临时文件、`importing` 和 `needs_rebuild` 遗留。
- 磁盘满、文件锁、只读目录和路径冲突必须返回可行动的错误。

### H1.5 检索与规模

- 对重复片段、极短查询、超长查询、特殊 FTS 字符和跨文档同名章节进行回归。
- 固定检索结果的来源隔离：deleted、superseded、index_failed 文档永不回流。
- 生成小/中/预期上限三档数据集，记录导入、重建、首次查询、热查询、内存和 DB/WAL 增长。
- 明确检索候选和缓存上限，避免一次查询加载全部向量造成不可控峰值。
- 扩充固定问答集之前先保证现有 12 题基线不退化。

### 当前优先验证的假设

以下只是代码审查假设，测试复现前不视为已确认 Bug：

- 导入队列中的任务可能在等待期间被取消，但轮到后仍开始落文件。
- 导入/重建末尾读取当前 Embedding 配置，可能与任务开始时实际使用的配置不一致。
- 同一文档重建与删除并发时，较晚完成的旧操作可能覆盖较新的生命周期状态。
- 全量重建与单文档重建可能重入。
- 工作区的“先检查文件不存在、再复制”在并发同名导入时存在占位竞争。
- 文档和工作区 IPC 的进度回调可能在发起窗口销毁后继续发送。

## H2：Electron、IPC 与 UI 生命周期复审

**目标**：长期打开和反复操作窗口时，不出现跨窗口串线、过期回调、监听器泄漏或退出顺序竞争。

### 任务

- 对所有 IPC 入口验证参数，不信任 renderer 传入的 ID、路径和结构体。
- 高权限 IPC 统一验证 sender；普通 IPC 也必须处理 sender/window 已销毁。
- 进度订阅、模型/任务/设置广播在窗口关闭后释放，并且重复打开不重复注册。
- 主窗口、悬浮窗、通话窗、提醒窗、设置/计划窗口反复创建销毁。
- 托盘、快捷显示、主题、人设、模型、Embedding 和性能设置跨窗口同步。
- 对象 URL、AudioContext、媒体流、React effect、定时器和事件监听器做生命周期检查。
- 更新检查、退出、后台 Agent、调度器、语音和数据库关闭顺序进行故障注入。
- 补 Electron smoke：窗口销毁后异步结果返回、重复窗口循环、应用退出时活动任务。

### H2 验收

- 连续创建/销毁各窗口至少 100 次无 listener warning、未处理 Promise 或僵尸窗口。
- renderer 销毁后主进程不再向它发送消息。
- 应用退出后进程可在限定时间内结束，数据库保持健康。
- 全量测试、构建和 Electron smoke 通过。

## H3：长稳、容量与恢复压测

- 数百次窗口开关、语音开始/停止和设置切换。
- 系统休眠/唤醒、长时间空闲、网络断开/恢复、应用强制结束后重启。
- 观察内存、句柄、WebSocket、定时器、SQLite WAL、临时目录和日志增长。

### 产物

- 可重复执行的 soak 脚本或测试入口。
- 每档运行时长、操作次数、峰值和结束后回落值。
- 失败注入后的恢复记录。
- 已知但不阻断发布的问题清单及阈值。

## H4：实机、安装包与发布收口

**目标**：把自动化无法证明的系统集成行为在真实安装环境中封口。

### 发布工程

- 解决或正式记录渲染端主 chunk 约 1.16 MB 的分包风险。

## 5. 总体验收矩阵

### 数据正确性

- 会话、记忆、任务、文档、chunks、FTS 和 Embedding 没有部分提交或旧状态回流。

### 并发正确性

- 同一资源的重复操作不会产生重复副作用。
- 旧异步结果不能覆盖新状态。
- 跨会话、跨窗口和后台任务互不串线。

### 资源正确性

- 成功、失败、取消、关闭窗口和退出应用均释放资源。

- Skill 文档、工具说明、IPC 类型、界面文案和实际行为一致。
- 错误信息可行动且不泄露密钥、上游正文或私人内容。

### 发布正确性

- 源码测试通过不代替构建、Electron、安装包和实机证据。
- 每个阶段的最终状态可以由命令输出、测试或验收记录复核。
