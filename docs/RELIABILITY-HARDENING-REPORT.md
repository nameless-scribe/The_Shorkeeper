# The Shorekeeper 稳固验收报告

> 版本：0.1.0  
> 日期：2026-09-13  
> 范围：现有 Skill、Agent、模型适配、调度、语音、RAG/工作区、Electron/IPC 与 Windows 发布工程  
> 结论：自动化和本机安装包工程已通过；实机硬件、真实云账号、干净机与代码签名尚待外部验收

## 1. 当前结论

现有 Skill 模块并不是唯一被稳固的部分。本轮已经继续覆盖 Skill 下游依赖的 Agent、调度器、语音、知识库、工作区、Electron 窗口/IPC、退出恢复和安装包生命周期。

在当前自动化边界内，未发现仍会阻断运行的已知回归。能力扩展继续暂停，直到实机和签名项目完成，或由项目负责人明确接受为已知限制。

## 2. 已形成的自动化证据

- `pnpm test`：123 个测试文件、563 个测试通过。
- `pnpm typecheck`、`pnpm build`、`git diff --check`：通过。
- `pnpm test:electron`：Electron 44.3.0 / Node 24.20.0 / ABI 149 运行时通过；100 次窗口轮换后窗口和 WebContents 均为 0，未处理拒绝和 listener warning 均为 0。
- `pnpm test:skills:ui`：Skill、诊断、路由原因和工具摘要在真实 renderer DOM 中可见，用户消息未泄漏。
- `pnpm stability:soak`：1000 轮会话/消息、1000 轮 Worldbook、1000 个 chunks 与强制中断恢复通过；`integrity_check=ok`，句柄增量为 0，sidecar 干净。
- `pnpm stability:runtime-soak`：200 个 Agent run、500 个后台任务、500 个 RAG 操作退出时全部收敛，数据库只关闭一次。
- `pnpm rag:capacity`：1,000 / 5,000 / 10,000 chunks 三档连续运行三次；参考档向量扫描中位数 9.1 ms、FTS 7.6 ms、RSS 增量中位数 48.45 MiB。
- `pnpm test:packaged-native`：安装包内 better-sqlite3 可加载，SQLite 3.53.4、WAL 和 trigram FTS 可用。
- `pnpm test:nsis-lifecycle`：首次安装、覆盖升级、卸载通过，外部数据库 SHA-256 前后相同。
- renderer 已按窗口和设置页懒加载；入口 chunk 约 154 KB，最大业务 chunk 约 460 KB，无 500 KB 构建告警。

## 3. 已关闭的主要风险

- Skill 文档、工具白名单、依赖/冲突、完成证据和真实文档场景不一致。
- Agent 重试、超时、取消、重复工具调用、多轮结果预算和退出收敛。
- 调度器超长计时溢出、忙碌任务搁置、同任务重入和未知动作误报成功。
- STT/TTS 断线悬挂、并发启动泄漏、音频分片缺失、播放/VAD 资源清理和输入容量失控。
- RAG 导入部分提交、并发变更旧状态回流、Embedding 非法结果、重建/删除隔离和工作区写入边界。
- Electron 高权限 IPC sender 信任、运行时参数验证、renderer 销毁后发送、窗口反复创建和退出阶段资源遗漏。
- 外观资源替换先删旧文件、Web 搜索设置持久化失败却报告成功等真实一致性问题。
- Windows 安装包内 native ABI、首次安装、覆盖升级、卸载和外部数据库保留风险。

## 4. 尚未完成且不能由自动化代替的验收

- [ ] 锁屏/解锁与休眠/唤醒相邻发生时无重复提醒。
- [ ] 真实断网期间聊天、Embedding、STT/TTS 给出可行动错误；恢复网络后无需重启即可恢复。

## 6. 是否需要更换技术选型

当前证据不支持为了“稳定”而整体更换 Electron、React、SQLite 或现有 Skill 机制。已发现的问题主要来自契约不完整、生命周期和输入边界，而不是底层技术无法达到目标。

只有出现可复现且现方案无法满足的门槛，才启动技术替换评审；评审必须同时记录失败门槛、替代收益、迁移成本、数据兼容和回滚方案。当前最优动作是完成上述实机验收，而不是开始新的架构迁移。
